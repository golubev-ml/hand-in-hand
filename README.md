# hand-in-hand

## О проекте

Мы рады представить проект благотворительной онлайн-галереи творческих работ детей, проходящих лечение от онкологических заболеваний. Наша миссия — поддержка детей и их семей через творчество, возможность почувствовать себя художниками, увидеть ценность своих работ и получить эмоциональную поддержку.

В этом году нашей организации исполняется 3 года. За этот период мы не только укрепили репутацию надежного социального партнера, но и реализовали важные инициативы:

- закрыли несколько крупных сборов на реабилитацию детей с инвалидностью;
- оказываем системную помощь 3 детским интернатам и кризисному центру для женщин;
- организуем адресную поддержку семей, ежемесячные благотворительные обеды и поздравления малышей с тяжелыми заболеваниями в их дни рождения.

Сегодня мы запускаем новый этап развития — благотворительную онлайн-галерею творческих работ детей с онкологическими заболеваниями. Для ребят, проходящих длительное лечение, искусство становится важным инструментом психологической разгрузки и реабилитации. Проект даст им возможность почувствовать себя настоящими художниками, поверить в свои силы и увидеть, что их творчество ценно и востребовано.

Мы активно ищем спонсоров и меценатов, готовых поддержать запуск галереи, техническое оснащение, создание сайта, а также проведение тематических выставок и мастер-классов для подопечных.

Мы будем рады обсудить любые форматы сотрудничества, включая партнерские программы и корпоративную социальную ответственность. Совместно мы сможем подарить детям веру в чудо и радость творчества.

По вопросам сотрудничества и для получения презентации проекта просим обращаться по контактам, указанным ниже.

## Запуск через deploy

Для запуска в Docker используйте профиль нужного окружения:

- `./deploy/deploy.sh test`
- `./deploy/deploy.sh prod`
- ./deploy/stop.sh

Скрипт загружает публичные параметры из `deploy/env/<окружение>.env`, затем локальные
`deploy/.env` и `deploy/secrets/<окружение>.env`/`*.env`. Секреты не входят в Git.
Он запускает базу, применяет миграции, собирает оба фронтенда и поднимает API.

## Домены

| Окружение | Основной сайт | Лендинг |
|---|---|---|
| test | `hand-in-hand-kzn.ru` — витрина `/`, API `/api`, админка `/admin`, возвраты `/payment` | `hand.hand-in-hand-kzn.ru/landing` |
| prod | `iskusstvo-chtoby-zhit.ru` — витрина `/`, API `/api`, админка `/admin`, возвраты `/payment` | `hand.iskusstvo-chtoby-zhit.ru/landing` |

Маршрутизация — traefik **v2.11** (на сервере старый Docker API 1.24, v3 не стартует),
сертификаты Let's Encrypt по HTTP-01, наружу опубликованы только 80/443. Лендинг
собирается из полноценного приложения `landing/` (бывший `variant2` из
`one-sheet-main`); префикс `/landing` снимается Traefik перед nginx.
По умолчанию профили поднимают встроенный proxy. При необходимости сервисы можно
подключить к уже работающему Traefik через внешнюю Docker-сеть; это задают
`USE_EXTERNAL_TRAEFIK` и `TRAEFIK_NETWORK`.

ID Яндекс Метрики задаётся через `YANDEX_METRIKA_ID`: он встраивается в витрину при
сборке и в лендинг при запуске контейнера. В production-профиле задан счётчик
`112702387`; в тестовом профиле сохранён прежний счётчик `112291835`.

## Оплата (HIH-9)

Тестовый контур Сбербанка `https://ecomtest.sberbank.ru/ecomm/gw/partner/api/v1/`.
Прямой протокол использует JSON; для test и prod нужны разные `userName` и пароли.
Включается чекбоксом «Оплата включена» в `/admin/settings` (по умолчанию **выключена**:
чекаут работает по прежней схеме-заглушке). Учётные данные шлюза хранятся в таблице
`settings`, секретные поля маскируются в админке и в логах.
