# Корневые сертификаты платёжного шлюза

Папка пустая по умолчанию: в репозитории не лежит ни один чужой сертификат, и
`deploy/Dockerfile` в этом случае просто ничего не делает.

Когда нужен файл сюда:

1. В логах оплаты (`/admin/logs`, строки `SBER … → СБОЙ`) появилось
   `certificate verify failed` / `unable to get local issuer certificate`.
   Это значит, что сертификат боевого шлюза выдан центром, которого нет в хранилище
   контейнера, — а на тестовом контуре проверка TLS отключена (`SBER_VERIFY_SSL=false`),
   поэтому там та же проблема не проявляется.
2. Запросите корневой сертификат у инженера интеграции Сбера (файл `.crt`/`.pem`)
   и положите его сюда, например `nuc-root.crt`.

Два способа заставить ему доверять:

**Вариант A — пересборка образа (рекомендуется).** Файл в этой папке →
`docker compose build api && docker compose up -d api`, и в контейнер добавить
`SSL_CERT_FILE=/etc/ssl/certs/ca-certificates.crt`, потому что httpx по умолчанию
использует bundle пакета `certifi`, а не системное хранилище.

**Вариант B — без пересборки.** Смонтированный файл и `SBER_CA_BUNDLE`:

```bash
# deploy/.env
SBER_CA_BUNDLE=/etc/sber-certs/nuc-root.crt
```

Папка `deploy/certs/` уже смонтирована в контейнер read-only как `/etc/sber-certs`.

Никогда не отключайте проверку TLS на боевом контуре (`SBER_VERIFY_SSL=false`) —
это открывает место для подмены шлюза.
